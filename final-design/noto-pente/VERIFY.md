## Conventions
- RED/GREEN: the "RED (before)" and "GREEN (after)" columns are the quoted lines qa must see. A row without a RED line is "not testable" with the reason.
- Fresh evidence: runtime verdicts use a tx made after the step's rollout. Served-build check before any Lensa run: `git -C frontend rev-list --count HEAD..origin/main` = 0 and `systemctl --user show lensa.service -p ActiveEnterTimestamp` after the last checkout update; else "stale build", no run.
- Namespaces: BEFORE `besu` (validators), `paladin` (nodes, gateways), `dfabi`. AFTER `rd-noto-bi`, `rd-noto-bank-a`, `rd-noto-bank-b` (cluster 1), `rd-noto-bank-c` (cluster 2, new only); per PLAN A1 the Noto CRs live where Z-NS puts the party's node (prefix substituted by lead if not `rd-noto-*`). qa uses each org's OWN kubeconfig, read-only.
- Ordering that binds qa: S1 (qa baseline) MUST be done before zeto S8 and S9 touch `paladin-node1..4`; zeto S8 must be a VERIFIED copy of the old Postgres, never an empty DB (addresses come from DB key mappings, not the seed alone).
- Lock/cap: a flow is a live write. `flock /tmp/lensa-paladin.lock` around ONE detached run, demo amounts, serial, lead GO, binding cap from the brief; release only by killing the holder qa started.
- BI-balance proof (flow steps S3, S12, S13): `frontend/web/e2e/flows/bi-delta.ts` noto: rd-issue 0/0, rd-transfer 0/0, dfabi-issue RD 0 / DFABI -3, dfabi-transfer 0/0, dvp 0/0, award RD +1,000,000 / DFABI -1. noto has NO top-up: a custodian DFABI below the amount is rejected before any lock (outright.ts:143-144), so the suite skips that flow up front (`precondition: BI DFABI=N does not cover M`, SKIP not FAIL). Command: `npx playwright test -c playwright.flows.config.ts e2e/flows/noto.flows.spec.ts` (worktree); expect `6 passed` (or named SKIPs) and one `BI-DELTA noto <flow> <RD|DFABI>: PASS` line per asserted cell. On the cutover (S13): BI custodian cash and bond equal the S1 baseline adjusted by the test amounts.
- Service-stop checks (BI node/notary down, a member down): NOT run by qa (cluster write; evidence = lead's window under the step's own CLUSTER-OP GO).
- Health: `env -u KUBECONFIG ROOT=$PWD bash agents/ops/post-reboot-check.sh` with `NAMESPACES` set to the live set for the phase; expect `rc=0`, no `FAIL`.
