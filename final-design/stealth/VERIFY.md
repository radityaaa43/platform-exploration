Owner: `qa`. Skills used: `superpowers:verification-before-completion` (a step is done only with fresh command output quoted; RED before, GREEN after), `web3-testing` (Foundry/Hardhat-style tests for Announcer, Registry, DvPFactory/DvPEscrow, DfabiBond roles and the signer's vitest suite).

Scope: qa is read-only. No cluster write, no new namespace, no restart, no delete by qa. Each step's CLUSTER-OP / user-only action is done by its owner under its own GO; qa runs the proof commands before (RED) and after (GREEN) and quotes both.

## Conventions
- RED/GREEN: the "RED (before)" and "GREEN (after)" columns are the quoted lines qa must see. A row without a RED line is "not testable" with the reason. `[unverified]` items stay until the owner's output confirms them.
- Fresh evidence: runtime verdicts use a tx made after the step's rollout/cutover. Served-build check before any Lensa run: `git -C frontend rev-list --count HEAD..origin/main` = 0 and `systemctl --user show lensa.service -p ActiveEnterTimestamp` after the last checkout update; else "stale build", no run.
- Secrets rule: never print key values. State checks count key FIELD NAMES only, e.g. `python3 -c "import json;d=json.load(open('state/stealth.json'));print(sorted(k for k in d if k in ('deployerKey','pool','biMeta')))"`.
- Namespaces: BEFORE `besu` (4 QBFT validators, PVs Retain), `paladin` (gateways `bank-gw-1..4` ports 38545-38548; Postgres PVs Delete), shared with zeto and noto-pente. AFTER `rd-stealth-bi`, `rd-stealth-bank-a`, `rd-stealth-bank-b` (cluster 1), `rd-stealth-bank-c` (cluster 2, new only; no other cluster-2 namespace is read). Gateways `st-gw-<N>` (N: 1 BI, 2 A, 3 B, 4 C), local ports 38641-38644 (`stealth-gw-<N> rd-stealth-<party> st-gw-<N> 3864<N>:8443`). qa uses each party's OWN namespace-scoped credential, read-only; JSON-RPC reads by `kubectl port-forward` with a read-only JWT (never started inside the flock).
- Lock/cap: a flow is a live write. `flock /tmp/lensa-paladin.lock` around ONE detached run, demo amounts, serial, lead GO, binding cap from the brief; release only by killing the holder qa started.
- BI-balance proof (flow steps S9, S10, S17, S19, S20): `frontend/web/e2e/flows/bi-delta.ts` stealth: rd-issue 0/0, rd-transfer 0/0, dfabi-issue 0/0, dfabi-transfer 0/0, dvp 0/0, award RD +1,000,000 / DFABI -1 (BI inventory: a free BI address with DFABI >= amount; with stock 0 a top-up fires: SKIP, not FAIL). Command: `npx playwright test -c playwright.flows.config.ts e2e/flows/stealth.flows.spec.ts` (worktree); expect `6 passed` and one `BI-DELTA stealth <flow> <RD|DFABI>: PASS` line per cell. The cutover proof (S20) adds: BI scanner holdings = bank scanner holdings.
- Service-stop checks (certificate signer scaled to 0, BI down): NOT run by qa (cluster write; evidence = lead's window under the step's own CLUSTER-OP GO).
- Health: `env -u KUBECONFIG ROOT=$PWD bash agents/ops/post-reboot-check.sh` with `NAMESPACES` set to the live set for the phase; expect `rc=0`, no `FAIL`.

## R1/R2/R3 proofs (S20)
- R1 (ACCEPTED by the user 2026-11-10, with the Lensa view-key GAP, A:5,132-133): amount, token and sender address are PUBLIC; recipient hidden. Playwright stealth flows: outsider column `partial`. Expected: `6 passed`. A bank re-registering a new viewing key blinds BI (A:133): the S11 compare job is the detective check.
- R2 (GAP for DFABI, certificate, A:135): DFABI transfers need the online cert signer; RD transfer, `settle()` and `cancel()` do not. The signer-down proof (S13) is NOT run by qa (cluster write; evidence = lead's window under the step's own CLUSTER-OP GO); qa records "GAP".
