## Conventions
- RED/GREEN: the "RED (before)" and "GREEN (after)" columns are the quoted lines qa must see. A row without a RED line is "not testable" with the reason.
- Fresh evidence: runtime verdicts use a tx made after the step's rollout (driver image, pod start). Served-build check before any Lensa run: `git -C frontend rev-list --count HEAD..origin/main` = 0 and `systemctl --user show lensa.service -p ActiveEnterTimestamp` after the last checkout update; else "stale build", no run.
- Namespaces: BEFORE `iroha3` (cluster 1: STS `bi bank-a bank-b bank-c`, `bi-auditor`, 6 PVs). AFTER `rd-iroha3-bi`, `rd-iroha3-bank-a`, `rd-iroha3-bank-b` (cluster 1), `rd-iroha3-bank-c` (cluster 2, new namespace only; no other cluster-2 namespace is read). qa uses each org's OWN kubeconfig, read-only. On-chain queries need signed requests (Torii `/v1/privacy/capabilities` answers 401, C:56): chain proofs go through the driver `wallet --party <p>`, the gateway ops, or the BI auditor store (`/records`), never Torii directly; `GET /status` and receipts `/v1/nexus/private-settlements/bundles/<id>/receipt` are the unauthenticated reads.
- Lock/cap: a flow is a live write. `flock /tmp/lensa-paladin.lock` around ONE detached run, demo amounts, serial, lead GO. Binding cap for the iroha3 suite (lead 2026-11-11): `IROHA3_TOPUP=1` only with a GO, at most 2 top-ups per flow and 6 per run, each exactly `topUpAmount()` (RD floor 3,000,000; DFABI floor 20); a third top-up for one flow aborts the run. Release the lock only by killing the holder qa started. STOP and report on `Driver APS gagal` / ENOENT / `connection closed before message completed`; no retry without a GO.
- BI-balance proof (flow steps S10, S13, S16, S18): `frontend/web/e2e/flows/bi-delta.ts` iroha3, per cell: rd-issue RD -1001 / DFABI 0; rd-transfer 0/0; dfabi-issue RD -1 / DFABI -3; dfabi-transfer RD -1 / DFABI 0; dvp 0/0; award RD +1,000,000 / DFABI -1. The fee cells (rd-issue RD, dfabi-issue RD, dfabi-transfer RD) are [re-derive after S10]: they hold only while BI is the sponsor (SPONSOR_REIMBURSEMENT 1 paid by the RD(leg 0) payer; with no RD leg a BI->BI 1 RD companion leg, C:63-65). Payer history rows must show `fee` "1" (rd-transfer A, dvp B, award C). Run: `IROHA3_TOPUP=1 npx playwright test -c playwright.flows.config.ts e2e/flows/iroha3.flows.spec.ts` (run 1), then without it (run 2): run 1 `6 passed`; run 2 `4 passed, 2 skipped` (dvp/award SKIP = "insufficient payer note (rejected before proving)", no write) or 6 passed; never a FAIL. On the NEW chain also: BI RD/DFABI balances equal the issued amounts less transfers (S18).
- Abort truth: receipt `"status":"aborted"` on all four nodes (C:55); a `pools.json` entry with height 0 after a failed run is NOT a reservation.
- Service-stop checks (peer, auditor, gateway down): NOT run by qa (cluster write; evidence = lead's window under the step's own CLUSTER-OP GO).
- Health: `env -u KUBECONFIG ROOT=$PWD bash agents/ops/post-reboot-check.sh` with `NAMESPACES` set to the live set for the phase; expect `rc=0`, no `FAIL` (today `PASS pods iroha3 12 pods ok`).
