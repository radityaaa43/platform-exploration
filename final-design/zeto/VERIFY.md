## Conventions
- RED/GREEN: the "RED (before)" and "GREEN (after)" columns are the quoted lines qa must see. A row without a RED line is "not testable" with the reason. `[unverified]` method names stay until the owner's output confirms them.
- Fresh evidence: runtime verdicts use a tx made after the step's rollout/cutover. Served-build check before any Lensa run: `git -C frontend rev-list --count HEAD..origin/main` = 0 and `systemctl --user show lensa.service -p ActiveEnterTimestamp` after the last checkout update; else "stale build", no run.
- Namespaces: BEFORE `besu` (4 QBFT validators, PVs Retain), `paladin` (4 nodes, Postgres PVs Delete), `dfabi`. AFTER `rd-zeto-bi`, `rd-zeto-bank-a`, `rd-zeto-bank-b` (cluster 1), `rd-zeto-bank-c` (cluster 2, new only; no other cluster-2 namespace is read). qa uses each party's OWN namespace-scoped credential (output of S1), read-only; JSON-RPC reads by `kubectl port-forward` (never started inside the flock).
- Lock/cap: a flow is a live write. `flock /tmp/lensa-paladin.lock` around ONE detached run, demo amounts, serial, lead GO, binding cap from the brief; release only by killing the holder qa started. Zeto flows are serialized (nullifier SMT divergence).
- BI-balance proof (flow steps S9, S19, S21): `frontend/web/e2e/flows/bi-delta.ts` zeto: rd-issue 0/0, rd-transfer 0/0, dfabi-issue 0/0, dfabi-transfer 0/0, dvp 0/0, award RD +1,000,000 / DFABI -1 (needs BI DFABI >= 1, else a batch top-up mints: SKIP, not FAIL). Command: `npx playwright test -c playwright.flows.config.ts e2e/flows/zeto.flows.spec.ts` (worktree); expect `6 passed` and one `BI-DELTA zeto <flow> <RD|DFABI>: PASS` line per cell. The cutover proof (S21) also compares the same tx `0x664c1faf2f09...` per party before and after.
- Service-stop checks (BI node down, a validator down): NOT run by qa (cluster write; evidence = lead's window under the step's own CLUSTER-OP GO).
- Health: `env -u KUBECONFIG ROOT=$PWD bash agents/ops/post-reboot-check.sh` with `NAMESPACES` set to the live set for the phase; expect `rc=0`, no `FAIL`.
