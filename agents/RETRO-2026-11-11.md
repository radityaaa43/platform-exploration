## What wasted time (finding, evidence, root cause, change, metric)

### Hooks blocking already-decided actions (5 of 7 self-retrospectives)
1. First-touch fact gate bounces writes to own files. Evidence: besu "~3 wasted round trips per task"; fabric "2 calls
   each, no new information"; fe "~5 ordinary calls" blocked. Root cause: the gate has no path classes.
   Change (user settings): exempt `agents/<role>/STATE.md`, the scratchpad and a role's own scratch clones.
   Metric: identical retry after a bounce <= 1 per role per day.
2. Destructive-command hook blocks after facts are stated. Evidence: orchestrator "blocked `git rm` twice even after
   facts stated"; iroha "3 retries", own `ci-red-*` branches left on the remote. Root cause: the hook does not read the
   answer it asked for. Change (user settings): allow `git branch -d` / `git push --delete` on a role's own `ci-red-*`
   branches and `git rm` of files named in a lead directive. Metric: user-run commands an agent had justified = 0 per day.

### Decision rights
3. Reversible deletes and relays cost user round trips. Evidence: orchestrator "every relay hop adds 5 to 15 min";
   a merged-branch delete and a worktree delete each took a user answer; 5 unique `USER DECISION` in 2 days.
   Root cause: "deletes are user-only" has no reversibility threshold. Change (user decides): lead owns deletes of
   merged-and-pushed branches and clean worktrees; the user keeps data deletes (PVCs, chain data, docker prune).
   Metric: user approval requests <= 3 per day.

### Shared checkout
4. Parent checkout switched under a running agent. Evidence: fabric commit 88ada83 landed on docs/decision-ladder,
   PR #12 rebuilt (~15 min); orchestrator checked out a stale master and deleted 256 files (restored in 2 min).
   Root cause: one working tree for parent-repo work; PR #15 fixed the rule, nothing enforces it. Change: the checker
   fails when a commit touching `agents/` was made from the main checkout path. Metric: wrong-branch commits = 0.

### Duplicated and contradictory docs
5. Role files copy TEAM.md rules. Evidence: 1427 lines in agents/ (TEAM.md 347, lead 175, fe 155 against the
   150 limit); 20 rules repeated, 8 of them in 5 to 6 role files; lead "a rule change needs six edits"; fe "the 30-line
   STATE.md cap costs a trim every update". Root cause: each role file written standalone and grown by appending.
   Change: shared rules live once in TEAM.md; role files hold role-specific content only, in the STYLE.md order.
   Metric: every role file <= 150 lines, TEAM.md shorter than 347, checker exit 0.
6. Rule conflicts and dead references. Evidence: 12 conflicts (docker prune ask-first vs never; lensa.service
   restart never vs approval; lead re-reads every diff vs does not; two owners of agents/; a qa rule resting on the
   unbuilt §10 check); dead references `rd-dfabi.toml`, `docs/adr/`. Root cause: no single owner per rule, no check that
   rules agree. Change: one rule per conflict (never beats ask-first where the user said never), dead references fixed,
   each conflict and its resolution listed in the rewrite PR. Metric: conflicts 12 -> 0, unresolved references 0
   (agents/blockchain/NOTES.md stays as the accepted exception).
7. The docs checker reports template noise. Evidence: 62 of 64 checker lines are duplicate template headings.
   Root cause: the skeleton headings are shared by design. Change: allow the STYLE.md skeleton headings
   (role statement, How to start, Always, Ask first, Never, Report), flag every other duplicate heading and any bullet
   repeated in 3 or more role files. Metric: checker false positives 0, exit 0 after the rewrite.

### CI evidence
8. CI result depended on cache state. Evidence: false-green runs 42970735154, 42971654363, 42971655697 (restored
   cargo target newer than the checkout, cargo fingerprints by mtime); fabric's first rdbi.yml run red on a cold cache.
   Root cause: RED/GREEN proved a test result, nothing proved the job rebuilt the code. Change: done in node-build
   PR #9 (0a27b3d): touch sources after the cache restore and fail unless the log shows `Compiling rd-dfabi`; a CI change
   is tested in a clean environment before its first push. Metric: false greens = 0.
9. Serial CI waits. Evidence: iroha "3-5 min per RED and per GREEN (5 PRs = ~40 min)", 6 min lost watching the old
   head after a rebase. Root cause: the watcher follows a run id, not the head sha. Change: push RED and GREEN heads
   together, watch by head sha (`gh run list --commit <sha>`). Metric: CI wall time per driver PR <= 5 min.

### Context loss at restart and compaction
10. Compactions, restarts and STATE.md drift. Evidence: compactions 2 (2026-11-10) -> 19 (2026-11-11); 17 sessions
    started on 2026-11-11; lead's STATE.md carried a dead session ref after a peer restart; 4 STATE.md files over the
    30-line cap; orchestrator had no STATE.md until today. Root cause: STATE.md copies session refs and is not checked;
    long diffs are re-read after compaction. Change: no session refs in STATE.md (ListAgents is the source), STATE.md
    in the checker (<= 30 lines), every PR description carries a 5-line review summary. Metric: stale refs 0,
    STATE.md <= 30 lines in 7 of 7.
11. A session-start rule peers cannot execute. Evidence: iroha "CLAUDE.md 'invoke /i-have-adhd at session start' cannot
    be done by a peer session". Root cause: a global instruction for the user-facing session applies to every session.
    Change (user settings): restrict it to the orchestrator session. Metric: session-start failures from it = 0.

### Report shape and unchecked claims
12. Asks buried in long reports; unchecked claims relayed. Evidence: orchestrator "lead reports that bury the ask in
    30 lines"; lead "messages over 40 lines where the ask is at the bottom"; 8 correction messages in 2 days (besu
    "26 lines, not 29"; orchestrator's test_red attribution). Root cause: no fixed report shape, no origin tag on
    claims. Change: first line `NO ACTION` or `DECISION NEEDED: <one line>`, at most 15 lines, detail by file path;
    a relayed claim reads `verified: <command>` or `unverified, from <role>`. Metric: 100% of lead -> orchestrator
    messages start with the marker; corrections <= 2 per day.

### Tooling and briefs
13. Disk-full hazards. Evidence: orchestrator "`du` on a 99% full disk timed out 3 times (2 to 5 min each)", 2 duplicate
    background `du` runs; fabric "305 MB scratch clone on a 99% full disk". Root cause: no cheap disk status.
    Change: one `df`-based check run by lead; no scratch clones above 90% use (report, per the no-prune rule).
    Metric: `du` calls over 60 s = 0.
14. Work launched without the constraints that cancel it. Evidence: besu "O2' spike (hours) rejected by the user's
    no-custom rule"; qa "two ~2 min live runs burned" on a red it could not read the cause of; lead's wrong hypothesis
    (withDeadline) sent iroha on a docker-events detour [weak]. Root cause: the brief carried the goal, not the user
    rules that exclude options nor the file:line of asserted values. Change: brief section 6 names the user rules that
    exclude options, section 2 cites file:line for every asserted value. Metric: tasks cancelled by a known user rule
    after start = 0; `BRIEF INCOMPLETE` <= 1 per day.

## Decisions for the user (defaults in brackets)
